## 目标 / 产出

- 第一个 **skill 算不出结论**的 Specialist
- 回放的定义被迫改了一次
- 一个「看起来像重要性标记、实际全是常量 0」的字段
- 两个额度参数，**都是测出来的**；其中一个第一版定错了

---

## 为什么这么做

### 1. 前五个 Agent 的形状是一样的，news 打破了它

market / sector / technical / emotion / risk 的分工完全相同：

```
skill：把数字算完，附证据      →      agent：复述 + 从词表挑一个 stance
```

agent 在这个结构里做的其实很少 —— 它主要是个**翻译层**。
这不是设计缺陷，是刻意的：铁律 3 说「Agent 不做算术」，
因为 LLM 算错不报错、且不可回放。

news 把这个结构顶破了：**「这条消息是利好还是利空」没有算式。**

于是两条铁律第一次指向同一个方向：

| 铁律 | 在 news 上的含义 |
|---|---|
| 3 · Agent 不做算术 | 条数、时间、覆盖度由 skill 算 |
| 4 · skill 不做判断性归类 | 消息的**含义**留给 agent |

⇒ skill 的产出是 **事实 + 原文**。它不打情绪分，也不分利好利空。

### 2. 🔴 回放的定义被迫改了一次

前五个 Agent 的回放是确定的：同样的输入，Python 必然给出同样的数。
所以「回放结果不一致」直接等于「有 bug」。

news 不成立 —— 判断由模型做，**同样的输入可能给出不同的 stance**。

这不是缺陷（人类分析师也这样），但它把一个二值判据变成了连续的。
关键在于别让它变成**不可观测**的：

1. 原文（含 `id`）随证据冻结进 `agent_verdicts`
2. 回放时喂**同一批 id 与同一段文本**（`content_sha256` 可校验）

> 有了这两步，「输入相同而结论不同」就从一个无法排查的现象，
> 变成一个**能被统计的量**。
>
> 没有这两步，结论不同时你分不清「模型飘了」还是「新闻变了」——
> 而这两者的应对完全相反。

## 坑

### 坑 1 · 🔴 `is_focus` 是个常量 0

探活时第一眼看到这几个字段就兴奋了：

```
is_focus    top_value    tab
```

名字都像「重要性标记」—— 正好可以用来筛出重要新闻。

实测 100 条：

```
is_focus 分布: Counter({0: 100})
top_value 分布: [(0, 100)]
tab 分布: [('', 100)]
```

**全是常量。** 照着它们设计过滤器，会得到一个永远选出空集的过滤器 ——
而空集在下游表现为「今天没有重要新闻」，**不会报错**。

> 通用原则：**字段名不是契约，返回值才是。**
> 这是开发流程第 1 条「设计先探活」的第二次兑现
> （第一次是 market 那个 `涨跌幅=-29971017728.0`）。

### 坑 2 · 这个源的「0 条」和行情源的「0」意思相反

14 章记过一个坑：盘前不同端点对「新一天还没开始」的表现是**相反**的 ——
实时源清零、历史源保留旧值。

news 这里又翻了一次。实测夜间每小时条数：

```
2026-09-21 00 → 3 条     03 → 12 条     06 → 16 条
2026-09-21 01 → 21 条    04 →  9 条     07 → 16 条
```

**凌晨一点都有 21 条。** 所以这个源的「0 条」不可能是「今天没新闻」，
只可能是取数失败。

⇒ news 不需要「盘前守卫」，它需要的是相反的东西：**静默即故障**。

```python
if not items:
    raise SourceError(
        "7x24: 一条都没取到 —— 本源实测凌晨 1 点仍有 21 条/小时，"
        "0 条意味着取数失败，不是「今天没新闻」")
```

> 通用原则：**「空」的含义由数据源的性质决定，不能跨源沿用。**
> 同一个 `0`，在一个源里是「还没开始」，在另一个源里是「坏了」。

### 坑 3 · 🔴 第一版额度定错了，而它表现为一个 PASS

第一版我拍了两个数：窗口 180 分钟、上限 40 条。理由是「3 小时够看，
40 条不会让 prompt 太大」。跑一次：

```
news  completed/PASS
  窗口内条数        = 250
  交给 agent 读的条数 = 40
  因上限未展示的条数   = 210
```

**agent 只看到 16% 的消息，verdict 却是 PASS。**

这就是 R-3 要防的静默 fail-open，而且形状特别隐蔽：
没有任何东西坏掉，每个数字都是对的，只是它们合起来在撒谎。

#### 修法不是加个警告，是重新定额度

第一反应是加一条 warning「只展示了 40 条」。不够 ——
warning 不影响 verdict，Card 上还是 PASS。

第二反应是改成 missing。方向对，但那样**每次盘中都会红** ——
一个每次都在的缺失项就是噪音（这条教训在 13 章）。

所以要先回答开发流程第 7 条那个问题：**什么时候不该红？**

按实测分布重新定额：

| 窗口 | 条数 | ≈token |
|---|---|---|
| 30 分钟 | 43 | 3.4k |
| **60 分钟** | **93** | **5.9k** |
| 120 分钟 | 179 | 14k |
| 180 分钟 | 245 | 22k |

⇒ 窗口 60 分钟、上限 120 条。盘中典型 93 条 < 120，**正常不截断**。
于是截断真发生时，它说的是「消息量突然翻倍」—— 一个有信息量的信号。

实跑验证：91 条，展示 91 条，截断 0 条。预测的 93 和实测的 91 对上了。

> 代价是这个 agent 只能就**最近一小时**发言。
> 这是一个**诚实的小范围**，好过「三小时」这个读了 16% 就敢下的大结论。
>
> 通用原则：**先定"什么时候不该红"，再定阈值。**
> 顺序反过来，就会得到一个要么永远红、要么永远不红的守卫。

### 坑 4 · 过滤是判断，打标才是事实

盘中 100 条里 21 条是机器行情播报：

```
深证成指涨1.00%，现报13777.470点；上证指数涨0.44%，现报3929.027点
中证500指数期货连续主力合约日内涨1%，现报7717.60点
```

这些数字是 `market` / `sector` 已经权威产出的事实（裁定 15）。
直觉是把它们**过滤掉**。

但过滤是**判断性归类**（铁律 4），而且代价不对称：
一个正则误伤一条真消息，下游完全看不出来 —— 那条消息就这么消失了。

⇒ 改成**打标**：`is_quote: true`，仍然交给 agent，由契约明令
「不许从快讯里提取任何行情数字」。

**而且要承认这个标记不准。** 实测带【标题】的豁免会漏标真播报：

```
【国债期货开盘】30年期主力合约涨0.16%，10年期主力合约涨0.01%…
```

不去调正则追它 —— 那是拿一天的样本过拟合。要做的是**把定位写清楚**：

> **标记是提示，契约才是防线。** `quote_count` 是下界，不是精确计数。

### 坑 5 · 单一生产方守卫抓到了「同名不同事实」

加完 news 跑全量测试，红了：

```
test_每个事实字段只有一个生产方[session_live] —— {'news-scan', 'risk-check'}
```

今早刚修过它的**反面**（`market.sh_close` 和 `technical.close` 是同一个事实
换了两个名字，守卫看不见）。这次是镜像：

```
周六 10:00
  session_in_progress(当天数据) = True    ← 这批数据所属交易日还没过完
  market_is_open()             = False   ← 此刻市场在不在交易
```

**同名、不同事实、值还相反。**

改名 `market_open`，并在两个函数的 docstring 里写清它们回答的不是同一个问题。

> 两种都要防，而且理由不同：
> **同一事实两个名字 → 守卫看不见；同名两个事实 → 人以为是一个数。**

### 坑 6 · 🔴 契约说 spawn 五个，配置只允许四个，中间没有任何报错

news 建好、注册好、写进 Supervisor 契约。跑端到端：

```
10:37:18  technical / market / emotion / sector     ← 只有四个
```

`news` 没被 spawn。Card 照常产出，**没有任何报错**。

原因在一个完全不同的文件里：

```json
"main": { "subagents": { "allowAgents": ["emotion","market","sector","technical","risk"] } }
```

一条**显式白名单**，里面没有 news。

#### 这个坑真正麻烦的地方是它误导排查

`risk` 会如实报「Stage 1 缺席：news」。看到这句，任何人的第一反应
都是去查 news agent 建得对不对 —— 而问题在运行时配置里。

> 这与「`agents.entries.*.skills` 是替换语义、不与 defaults 合并」同一族：
> **配置里的"白名单"默认是排他的，而排他的失败是静默的。**

⇒ 加 `tests/test_roster_matches_config.py`，三个方向对账：
已建 → 注册 / 已建 → 白名单 / 契约声明 → 已建。
