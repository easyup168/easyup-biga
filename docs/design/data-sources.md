## 0. 这份文档要回答的问题

不是「我们用了哪些源」——那个 `bin/biga-data providers` 就能列。
是下面这三个**换源时才会问、而那时已经来不及查**的问题：

| 问题 | 为什么重要 |
|---|---|
| 这个 dataset 挂了，有没有第二条路？ | 没有备胎 ⇒ 源一挂，当天整条链停 |
| 备胎和主源**口径一样吗**？ | 不一样却当等价用 ⇒ 降级那天的数悄悄变了含义 |
| 换到备胎之后，**还剩几道校验**？ | 有些校验依赖主源特有的字段，换源后会**静默退化成恒等式** |

🔴 第三条最容易漏。举一个本仓库真实的例子：
`cn.security_master` 的质量策略里有一条「provider 自报总数 vs 实际归一化条数」。
备用源**不自报总数**，于是那道校验在降级时两边恒等 —— **它还在跑，但什么都没查**。

> **一道在降级时退化成恒等式的校验，比没有这道校验更危险：
> 它让人以为那天也被查过。**

## 1. 参考的两个来源

| 来源 | 是什么 | 我们怎么用它 |
|---|---|---|
| `a-stock-data` | 公开的 A 股数据源目录（Apache-2.0）：15 层、87 端点、34 个源，带「备用源速查 & 降级策略」表 | **查端点与可用性排序**。它把东财标为「接口共用同一套风控，IP 被封会成片失联」，建议优先用不封 IP 的源 |
| 同机另一套长期运行的实例 | 每天真的在跑的 A 股数据管线 | **查哪条路经得起天天跑**。它不是「听说能用」，是连续在产 |

⚠️ 两者的作用不同，不要互相替代：
前者告诉你**有哪些选择**，后者告诉你**哪个选择扛得住日复一日**。

🔴 **它们都不能代替自己探活。** 本仓库第一条开发流程就是「设计先探活」，
而这一轮两次推翻了看起来可靠的结论：

1. 我按「字段更齐」选了东财 `datacenter-web` 做 security_master 备胎，
   探活发现它是**机构信息表**（24780 条，含早已退市的），口径根本不对
2. 我按「新浪给的是手」写了 `×100` 换算，
   实测 `(amount/close)/volume` 中位数 = **1.006** —— 单位是**股**，
   ×100 会让全市场成交量大 100 倍，而那**不会报错**

## 2. 12 个 ACTIVE dataset 的供数关系

判据在代码里（`src/easyup_biga/data/registry.py` + `src/easyup_biga/data/provider_registry.py`），
这张表是**给人读的摘要**，不是第二份真相。查当前状态用：

```bash
bin/biga-data providers --json
python3 tools/verify/phase3_runtime.py --installed
```

| dataset | 主源 | 备用源 | 换源后失效的校验 |
|---|---|---|---|
| `cn.security_master` | 东财 `clist` | **新浪 `hs_a`** | 自报总数交叉校验；上市日（`list_date` 全空，进 `missing_list_date_count`）|
| `cn.equity.daily_bars` | **新浪 `hs_a` Simple** | 东财 `clist` | 自报总数交叉校验（新浪不自报）|
| `cn.trading_calendar` | 新浪日历 | 深交所官方 | 备用源按月取、**缺未来排期** ⇒ 标 `degraded` |
| `cn.security.tradability` | 派生（`derived_biga`）| — | 派生无外部源；血缘引用日线那条 raw |
| `cn.market.emotion_close` | 派生（`derived_biga`）| — | 同上，血缘引用股池那条 raw |
| `cn.equity.adjustment_factors` | CSV 导入 | — | 人工导入，无自动源 |
| `cn.index.daily_bars` | 新浪 K 线 | — | |
| `cn.index.realtime_quote` | 腾讯 | — | |
| `cn.market.breadth` | 东财 | — | |
| `cn.sector.board_snapshot` | 东财 | — | |
| `cn.market.limit_pool` | 东财 `push2ex` | — | |
| `cn.news.flash` | 新浪 7×24 | — | |

### 2.1 🔴 五个盘中 dataset **一个备胎都没有**

`breadth` / `board_snapshot` / `limit_pool` 三个走东财，`realtime_quote` 走腾讯，
`news.flash` 走新浪 —— `fallback_providers` 全是空的。

2026-09-26 那次真机出卡，三个东财 dataset **同时**失败（`push2` 整组故障），
卡上的 `missing` 如实报了，但那一天的决策**少了三分之一的输入**。

⚠️ 这不是「忘了配」：登记一个**没探活过**的备胎，等于承诺一条
可能也是断的降级路径 —— 那比没有备胎更糟。
⇒ 补备胎的正确顺序永远是「先探活、再登记」，不是「先登记、出事再说」。

### 2.2 为什么日线的主源是新浪而不是东财

2026-09-26 对调。依据**不是**「东财那天挂了」（那只是触发），是两条长期证据：

1. 同机另一套长期运行的实例，每天的全市场日线走的就是新浪
   `Market_Center.getHQNodeDataSimple`（`node=hs_a`，`num=500`）
2. `a-stock-data` 把东财标为「共用同一套风控，IP 被封会成片失联」，
   并建议优先用不封 IP 的源

⚠️ 口径差异（写在 `src/easyup_biga/providers/sina_eod.py` 模块头里，不当等价替换）：

| | 东财 `clist` | 新浪 `hs_a` |
|---|---|---|
| 成员 | 板块过滤串 | 行情节点，**当前在交易的** |
| 自报总数 | 有 | **没有** |
| 停牌股 | 返回，OHLC 为 `"-"` | **不返回** |
| 成交量单位 | 股 | 股（**实测**，见下）|

🔴 **停牌股不返回，不是缺陷，但它改变了下游的理由。**
`cn.security.tradability` 用「在 universe 里、当日没有价」区分停牌与数据缺失。
两个源在那里都归到同一种状态，**结论不变、理由不同** ——
别把「没返回」读成「源坏了」。

## 3. 一道用真实事故换来的守卫：成交量单位

同机那套实例的代码里留着一句注释：

> 成交股数用 `amount/close` 推，不用 `volume` —— **volume 单位跨某日变过**。

也就是说这个字段的单位**在历史上真的漂移过一次**。

⇒ 本仓库不写死倍数，改成**每次取数都自检**：
`(amount / close) / volume` 的中位数应当接近 1。
上游哪天改回「手」，这个比值跳到 ~100，当场 fail closed。

```python
# src/easyup_biga/providers/sina_eod.py
_VOLUME_UNIT_WINDOW = (0.5, 2.0)
```

窗口取得宽是故意的：分子用收盘价、分母是全天成交量，本来就有
VWAP 与收盘价的偏离（实测当日 p5/p95 = 0.99 / 1.02）。
**这道守卫抓的是数量级跳变，不是精度。**

样本不足 20 只时**宁可失败**，不假装查过。

## 5. 不做的事

### 5.1 不导入另一套系统的历史库

裁定 1 写着「完全独立，自己重新采数据，**不挂载对方的库**」。
除此之外还有两条技术理由，即使裁定改了也仍然成立：

1. **它解不开任何一个当前的阻塞。** 上线验收要的是「连续 5 个交易日
   EOD **跑通**」——判据是这条 pipeline 真跑过，不是库里有那几天的数。
2. 🔴 **导入的行没有 raw。** 本仓库的日线分区必须指回一份 RawArtifact
   （原始响应字节 + `content_sha256` + `retrieved_at`）。导入只有两个选择：
   不给 raw（发布服务 fail-closed，发不出去），或者拿导入的行**自己序列化
   一份当 raw** —— 那正是「自己证明自己」，本仓库刚花一整轮修掉它。

   而且 `knowledge_cutoff` 不可知：证明不了某年某月那天的那份数据在**那一刻**
   长什么样。point-in-time 查询会因此给出一个看起来合理、却无法追溯的答案。

⚠️ **如果将来 Phase 4 的回测确实需要历史日线**，正确的做法是单独建一个
dataset（而不是往决策链的那个里灌）：它自己的 provider id、显式声明
`effective_trade_date`、raw 是**那次导入的原始导出文件本身**（那是诚实的：
它确实是我们收到的字节），并在注册表里写明「非 point-in-time，
不能用于回答『当时看到的是什么』」。
