# BigA 开发流程

> ⚠️ 用户级 `~/.claude/skills/dev-workflow` 是**邻居项目**的流程。
> 它引用的是邻居的目录结构与远端部署流程，其中一步要求写邻居的状态目录 ——
> **照它的 Track D 做会直接破坏不变式 I-1**。本仓库用这一份。

---

## 0. 每次动手前

```bash
cd ~/.openclaw-biga/workspace
git status                 # 有未提交的东西先弄清楚
python3 -m pytest -q       # 记下基线条数
```

改前先读目标文件，并看 `git log --oneline -5 -- <file>` 的上下文。
**不读就改，等于在别人的推理上叠自己的推理。**

---

## 1. 🔴 设计先探活，测试再离线

对外部数据源做任何设计之前，**先用 curl 打一次真接口**。

实测代价：market 的数据源选型完全来自探测 —— 发现唯一可达的主机返回
`涨跌幅=-29971017728.0`（而 `rc=0`、字段齐全、类型正确），
以及 `lmt=25` 被忽略返回全历史。

> 外部评审建议我们「Offline First, Live Last」。对本项目**恰好是反的**：
> 先写 fixture 等于把一个坏掉的 API 形状固化进测试。

⇒ **设计阶段先探活；测试阶段全离线**（依赖外网的测试会随机变红，
几次之后所有人都开始忽略它 —— 一个被习惯性忽略的测试等于没有测试）。

---

## 2. 加东西时的四个必答问题

| 问题 | 不答会怎样 |
|---|---|
| 这个**事实**已经有生产方了吗？ | 两个 agent 各算一遍，某天悄悄给出两个数（裁定 15） |
| 这个模块写的数据，**谁读**？ | 零消费方组件（L-1）。判据是**调度命令的字面量** |
| 它会被 **LLM 转述**吗？ | 会就别让它经过 LLM —— 落库传 id（L-10） |
| 这条信息属于 **`missing` 还是范围外**？ | 范围外塞进 `missing`，就成了每次都在的常驻噪音 |

---

## 3. 每加一个守卫，用探针验证它会红

```bash
# 1. 临时把守卫拆掉（或植入一个违规样本）
# 2. 跑对应的测试，必须 FAILED
# 3. 恢复，必须全绿
```

**守卫写了却没见它红过，和没写是一回事。** 本仓库靠这条抓到过：
一个假的审查脚本（永远自匹配）、一个扫不到新分支的 pre-push、
一个在正确行为上报红的并行判据。

⚠️ 探针脚本自己也会有 bug（本仓库踩过：恢复文件那行用了未定义的变量，
导致后面几条探针结论全不可信）。**探针跑完必须确认工作区已还原。**

---

## 4. 重构：用两个独立信号证明它是空操作

不是「测试仍然全绿」，而是：

1. **测试条数与内容都没动** —— 改了测试，这个信号就脏了
2. **真跑一次，数字与改前逐字节相同**

实测用法：抽 `_sources` 共享层时「124 条一条不变 + 情绪分仍是 55.52」；
删 14 处冗余时区转换时 `diff before.txt after.txt` 逐字节相同。

## 5. 🔴 诊断「为什么这么慢」：先看工具调用序列，再改提示词

```bash
python3 tools/verify/agent_trace.py --agent <name> -n 1
python3 tools/verify/latency_report.py --parallel-check
```

本仓库两次最有价值的诊断都来自这个动作，**两次的第一反应都是
「提示词写得不好」，两次都错**：

- Supervisor 那 159 秒里有 **47 秒零工具调用** —— 在重打 JSON
- Specialist 加 stance 后慢一倍 —— **62 秒都在 grep 源码找词表**，还跑了 `find /`

> **Agent 的「慢」，多数时候是它在找东西，不是在想事情。**

推论：**契约必须自包含**。写「见下表」之前先确认那张表真的在 ——
而且运行时可能吞掉命令输出（`[Malformed diagnostic JSON redacted]`），
Agent 连 `--help` 都未必读得到。

## 6. 端到端验证

```bash
# 🔴 必须开新会话，否则它会拿记忆回答，测不到你刚改的契约
BIGA=~/.openclaw-biga/bin/biga
$BIGA agent --agent main --session-key "agent:main:e2e-$(date +%H%M%S)" -m "..."
```

⚠️ **等 Supervisor 那一轮结算完再测量。** 它是在自己那一轮的**中途**落卡的 ——
卡一出现就跑报告，会漏掉最大的一块。实测漏报过一次：
报 41.5s「达标」，而缺掉的合成轮是 159.1s。

改了环境（config / agent / gateway）之后再跑一次隔离自检：

```bash
stat -c '%y' ~/.openclaw/state/openclaw.sqlite   # 前后对比
[ ! -e ~/.nvm/versions/node/v24.21.0/bin/openclaw ] && echo "✅ R-2 未被破坏"
```

## 7. 指标：先问「它什么时候**不该**红」

新加任何检查/阈值，先回答这个。答不上来就说明它会变成噪音。

踩过的三次：
- 审查脚本的正则匹配到自己 —— 永远报 3 处
- risk 数「超过 120s 的证据条数」—— 周末必然全红
- 并行判据把 Stage 2 算进 Stage 1 —— 在**正确行为**上报红

> **在正确行为上报红的检查，比漏报更糟。** 它会被训练成噪音，
> 等哪天报的是真问题也没人看了。

---

## 8. 报错要指路

给 Agent 看的错误消息**必须包含下一步怎么做**，否则它会花几轮去猜。

```
❌ ValueError: missing 非空却给出 verdict='PASS'
✅ 追加了缺失项但没给 --verdict。
     核心指标齐备 → --verdict WARNING
     核心指标有缺 → --verdict UNKNOWN
```

## 9. 文档与提交

- **改代码就要改常青文档**（`docs/design/`）。规约见 `docs/README.md`，
  由 `tests/test_docs_convention.py` 强制
- **每段工作先写教程章节再往下做**（裁定 10）。教程的价值在于**当下的细节** ——
  一周后回忆只剩「装上了、能跑」
- **CHANGELOG 与代码同一个 commit**，条目写**为什么**不只是做了什么
- commit message 里**贴实测数字**（前后对比），这是三个月后唯一能复核的东西
- 🔴 **不许把「改了指标让红灯变绿」说成「修好了」** —— 两者都要写出来

```bash
tools/verify/audit_public.sh --worktree   # commit 前扫工作区
git push                                   # pre-push hook 自动扫增量
```
